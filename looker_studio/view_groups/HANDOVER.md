### 何をするツールか（1 段落）

`INFORMATION_SCHEMA` から View の定義を毎日読み、**suffix を除いた base 名ごとに
束ねて、SQL ロジックが同じもの同士でグループに分ける。** グループ数がその base の
ロジックの通り数になる（1 なら揃っている、2 以上なら差がある）。結果を
タブ付きの HTML として BigQuery の中で作り置きし、Looker Studio の
**Templated Record** がそれをそのまま描く。

## 5. 壊してはいけない決めごと

**どれも「壊れてもエラーが出ない」もの。** 画面は正しく見えるのに中身が違う、
という形で出るので、知らずに触ると気づけない。

### `viewlgc_panes` と `viewlgc_render` は添字で対応する

ペインの並べ方の規則（基準を除いた残りを `MAX_TABS` 件まで）を**両方が持って
いる。** 片方だけ変えるとタブと中身がずれる。

- **`ref_index` は両方に同じ値を渡す。** 片方だけだと「タブは基準 B なのに
  中身は基準 A のペイン」になる。`node check_sql.mjs` が SQL の呼び出しを見張る
- **`__applyMode`（class への畳み込み）は render 側で最後に 1 回だけ。**
  panes は style 属性のまま返す。二重に畳むとハッシュの素が変わり、
  テンプレートの CSS と合わなくなる
- **配る CSS の fixture もペインを描く**（`buildPanes` を呼ぶ）。描かないと
  差分の markup のクラスが CSS に入らず、**貼ったのに色が付かない**

### `CSS_GEN` を上げたら 3 つ全部やり直す

世代の番号は **CSS だけでなくカードの markup にも入る**（`chrome.js` の
`cssGuard()`）。**両方の番号が一致したときだけ案内が消える。**
「見た目だけの変更だから UDF はそのままでよい」は誤り。いまは **11**。

### `suffixes` / `locations` / `view_names` は添字で対応する

`t_diff` の 3 本の配列。`base_views` が**同じ `ORDER BY` で畳む**ので対応は
構造で保証されている。値で結び直してはいない。配列は NULL を持てないので、
畳む前に代替を入れる（suffix → View 名 / region → 空文字）。**行ごと落とすと
添字がずれる。**

### `suffix` の切り出しは 1 か所だけ

`build_table.sql` の `keyed`（SQL 側）と `extractSuffix`（UDF 側）が
**どちらも最長一致**で同じ結果になるように書いてある。食い違っても落ちず、
列とカードで別の suffix が出るだけ。**確認クエリ 5-9 が 0 件であること。**

### `ddl_diff_viz/` は消せない

採らなかった方式だが**ビルド依存**。

```
build_udf.mjs ← ddl_diff_viz/src/lib/diff.js    を UDF に同梱
              ← ddl_diff_viz/src/lib/render.js  を同じく同梱
              ← ddl_diff_viz/package.json       から esbuild を引く
```

**`src/lib/` と `package.json` は動かさないこと。**

### `radio_tabs_test.html` がタブの根拠

Looker Studio のコミュニティ ビジュアライゼーションの中では **JavaScript が
動かない。** タブはすべて radio + `:checked` の CSS で切り替えている。

**効く形は `:checked ~ 親 > 対象`（子結合子）。** 子孫結合子に変えたら実機で
反転しなくなった。セレクタの形を変えるなら、まず
`view_groups/radio_tabs_test.html` を Templated Record に貼って確かめること。

### View 名はリージョン内で一意という前提

base の切り出しは View 名だけで畳む。**重複すると 1 本だけ採って残りが黙って
消える**（カラム定義も混ざる）。**確認クエリ 5-3b が 0 件であることが前提**で、
0 件でない状態が続くならデータセットまで含めた識別に作りを変える必要がある
（未対応）。

### UDF の本体は 1 個 32 KB まで

現在の余裕。**30 KB を超えたら生成が失敗する**（BigQuery に弾かれるものを
出荷しないため）。

| 関数 | 最小化後 | 上限比 |
|---|---|---|
| `viewlgc_analyze` | 11.1 KB | 37% |
| `viewlgc_panes` | 13.3 KB | 44% |
| `viewlgc_render` | 15.8 KB | 53% |
| `viewlgc_erd` | 20.1 KB | 67% |
| `viewlgc_page` | 21.6 KB | **72%** ← いちばん詰まっている |
| `viewlgc_markdown` | 6.5 KB | 22% |

詰まってきたら **依存が独立しているところで UDF を割る**（`UNUSED_*` の
見直しが最初の手）。それでも足りなければ `OPTIONS(library=["gs://…"])` に
移す（BigQuery はジョブの認証情報で読むので**非公開バケットで構わない**）。

## 6. 作業の進め方

### 検証スイート 5 本を必ず走らせる

```bash
cd looker_studio/view_groups
node test.mjs               # アナライザの判定          195
node preview.mjs            # 描画の markup と CSS      178
node build_udf.mjs          # UDF の生成物              76
node check_sql.mjs          # SQL と資料の突き合わせ    83
node check_cross_region.mjs # リージョン間の運搬        22
```

件数は 2026-10-21 時点。**増えるぶんは気にしなくてよい。**

**`build_udf.mjs` は esbuild が要る。** コンテナが作り直されると
`node_modules` が消えるので、最初に入れ直す。

```bash
cd looker_studio/ddl_diff_viz && npm install
```

esbuild が無いと最小化がスキップされ、UDF が 30 KB を超えて
**4 件失敗する**（コードの問題ではない）。サイズ検査に落ちると
**書き出す前に止まる**ので、生成物が汚れることはない。

### 資料は機械が見張っている

`check_sql.mjs` が、`usage.md` と `DEPLOY.md` が引用している**画面の文言と
数字**を本体と突き合わせる。

| 資料 | 見張っているもの |
|---|---|
| `usage.md` | 外側タブの並び / 打ち切りの案内文 / 読むオブジェクトの既定名 |
| `DEPLOY.md` | `ASSERT` の文言 / 確認クエリ 5-x の一覧 / 画面の上限 / 貼る順番 |

**落ちたら資料を直す。** 読む人にとっては資料と実物が食い違っているほうが困る。

### 新しい見張りを足したら、必ず改変して試す

このプロジェクトでは**検証が素通りしていた例が何度も出ている**。

- 生成した SQL を、それを組み立てた変数と比べていた（何も検知しない）
- 分割直後、`render` を 3 引数のまま呼ぶ検証が 2 件通っていた
  （引数が 1 つずれても、互いを比べ合うだけなら素通りする）

**足した見張りは、わざと壊して落ちることを確認する。**
