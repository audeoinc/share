# PRD: SQL Diff → Confluence HTML Exporter（VS Code 拡張機能）

**ステータス:** ドラフト v1
**対象:** 社内エンジニア（主に SQL 開発）
**作成日:** 2026-07-25
**オーナー:** Tony

---

## 1. Problem Statement（課題）

SQL 修正のレビューでは、修正内容を Confluence にまとめ、その一部として**修正前後のソース差分**を掲載している。開発は VS Code で行っており、VS Code の差分ビュー（compare）の見た目は非常に見やすいが、**その見た目のまま Confluence に貼れる HTML を出力する手段がない**。現状は差分を手作業で整形・貼り付けるため、レビュー資料の作成に手間がかかり、見た目も VS Code ほど分かりやすくならない。

さらに、VS Code の compare は **2 ファイルの比較しかできず**、3 ファイル（例: 修正前・修正後・参考）を並べて確認・共有したいケースに対応できない。

---

## 2. Goals（達成したいこと）

本機能の中心となるゴールは次の 2 つ。

- **G1. 差分掲載までの作業時間を短縮する** — VS Code の差分をそのまま Confluence に貼れるようにし、手作業の整形・貼り付けを最小化する。
- **G2. レビュー品質を向上する** — 差分を**正しく・もれなく**確認できるようにする。そのための手段が「**見やすさ**（VS Code compare 相当の視認性）」と「**提供のしやすさ**（Confluence へ崩れず簡単に載せられること）」。

この 2 つを実現するための具体的な達成条件:

1. VS Code の差分ビューと同等の見た目の差分を、**Confluence にそのまま貼れる HTML** として出力できる（→ G2 見やすさ）。
2. Confluence の **HTML マクロで崩れずに表示**される（＝すべてのスタイルがインライン CSS）（→ G1・G2 提供のしやすさ）。
3. **2 ファイルに加えて 3 ファイル**の差分比較に対応する（→ G2 もれのない確認）。
4. 差分掲載までの手作業をコピペ 1〜2 操作に短縮する（→ G1）。
5. **できるだけ早く開発版を社内提供**し、実運用でフィードバックを回せる状態にする。

> 補足: 見やすさ・提供のしやすさは「レビュー品質向上」の手段であり、それ自体が目的ではない。指標も作業時間だけでなく**レビューの正確さ・網羅性**を測る（§7 参照）。

---

## 3. Non-Goals（今回やらないこと）

1. **Confluence への自動アップロード / API 連携** — v1 は「HTML を生成してコピー」までとし、貼り付けは手動。連携は複雑さとConfluence 権限管理の都合で別イニシアチブ。
2. **HTML ファイルのディスク保存** — 意図的に保存しない（git を汚さないため）。プレビューとコピーのみ。
3. **4 ファイル以上の比較** — 需要が固まっていないため v1 は最大 3 ファイル。
4. **SQL 以外の言語への最適化 / 独自のセマンティック差分** — v1 はテキスト行差分ベース。SQL 構文解析による意味的差分は対象外。
5. **VS Code 標準 diff エディタの置き換え** — 既存の compare を置き換えるものではなく、HTML 出力という補完機能。

---

## 4. User Stories（ユーザーストーリー）

対象ペルソナ: **社内エンジニア（SQL 開発者 / レビュー資料作成者）**

- レビュー資料作成者として、エクスプローラーで **2 つのファイルを選択して右クリック**し、差分比較を起動したい。VS Code の compare と同じ見た目で差分を確認するため。
- レビュー資料作成者として、**3 つのファイルを選択した場合は 3 ファイルの差分**として表示してほしい。修正前・修正後・参考を一度に比べるため。
- レビュー資料作成者として、生成された差分を **VS Code 内でプレビュー**しながら、**HTML ソースをワンクリックでコピー**したい。Confluence の HTML マクロにそのまま貼るため。
- レビュー資料作成者として、コピーした HTML が **Confluence 上でも VS Code と同じ見た目**で表示されてほしい。読み手が差分を追いやすくするため。
- レビュー資料作成者として、生成物が**ファイルとして保存されない**でほしい。git の差分やコミットに影響を与えないため。
- 拡張機能の利用者として、**フォント・文字色・背景色・行間などのレイアウト**を設定で変えたい。チームや掲載先の見やすさに合わせるため。

### エッジケース / 状態

- 1 ファイルだけ選択した場合、または 4 つ以上選択した場合 → 明確なメッセージを出す（§5, P0）。
- 選択したファイルが空 / バイナリ / 巨大ファイルの場合の挙動。
- 差分が非常に大きい場合のプレビュー描画パフォーマンス。

## 5. Requirements（要件）

### Must-Have（P0）— これがないと成立しない

**R1. 右クリックからの起動（コンテキストメニュー）**
- **VS Code 内蔵のエクスプローラー**（サイドバーのファイルツリー）でファイルを選択して右クリックすると、メニュー項目 **「Export to Diff HTML」** が表示される。
- 受け入れ基準:
  - [ ] VS Code のエクスプローラーで複数ファイルを選択した状態の右クリックに「Export to Diff HTML」が出る
  - [ ] 2 ファイル選択時 → 2 ファイル比較、3 ファイル選択時 → 3 ファイル比較を**内部的に自動判定**して起動
  - [ ] 1 ファイル / 4 ファイル以上のときは分かりやすいエラーメッセージ **「2または3 個のファイルを選択してください」** を表示

**R2. VS Code compare 相当の差分表示を HTML 生成**
- 修正前後（および 3 ファイル）の行差分を、VS Code の差分ビューに近い見た目で HTML として生成する。
- 追加行 / 削除行 / 変更行の色分け、行番号を含む。
- 受け入れ基準:
  - [ ] 追加・削除・変更が VS Code と同様に色分けされる
  - [ ] 行番号が表示される
  - [ ] SQL のシンタックスが視認できる（ハイライトの範囲は §8 で確定）

**R3. インライン CSS のみで自己完結した HTML「フラグメント（部品）」**
- Confluence の HTML マクロに貼るため、`<style>` タグや外部 CSS に依存せず、**すべてのスタイルを各要素の `style` 属性にインライン**で持たせる。
- 出力は **`<!DOCTYPE>` / `<html>` / `<head>` / `<body>` を含まない部品**とする（Confluence ページ側のこれらのタグと競合するため）。**ルート要素は `<div>`** とし、従来 `body` に載せていた基準スタイル（font 等）は wrapper の `<div>` に持たせる。
- 受け入れ基準:
  - [ ] 生成物に `<!DOCTYPE>` / `<html>` / `<head>` / `<body>` が**含まれない**
  - [ ] ルートは `<div>` で、その1要素をコピーすれば貼り付け単位が完結する
  - [ ] 外部 CSS / `<link>` / `<script>` 依存がない
  - [ ] クラスセレクタに依存せず、Confluence の HTML マクロに貼って VS Code と同等の見た目で崩れず表示される

**R4. VS Code 内プレビュー（ソース + プレビューの左右 2 ペイン）**
- Webview パネルを開き、**左ペインに HTML ソース、右ペインにレンダリング済みプレビュー**を表示する。
- 受け入れ基準:
  - [ ] 左にソース、右にプレビューが並ぶ
  - [ ] 右のプレビューが生成 HTML の実際の見た目になっている
  - [ ] パネルは VS Code 内で開く（外部ブラウザを起動しない）

**R5. HTML ソースのコピーボタン**
- ソースペインに、HTML 全文をクリップボードへコピーする**コピーアイコン（ドキュメントが2枚重なった一般的なコピーアイコン）**を設置。
- 受け入れ基準:
  - [ ] ボタン 1 クリックで HTML 全体がクリップボードにコピーされる
  - [ ] アイコンはドキュメント2枚重ねの一般的なコピーアイコン
  - [ ] 完了フィードバック（トースト等）は**不要**（昨今のコピーアイコンと同様、明示的な完了表示は出さない）

**R6. ファイルを保存しない**
- 生成した HTML はメモリ / Webview 上のみで扱い、ワークスペースにファイルを書き出さない。
- 受け入れ基準:
  - [ ] 実行後にワークスペース内へ新規ファイルが生成されない
  - [ ] git status に影響が出ない

**R7. 3 ファイル比較の内部制御**
- 選択ファイル数に応じて 2-way / 3-way を切り替える。
- 受け入れ基準:
  - [ ] 3 ファイル選択時、3 つのソースの差分が 1 つの HTML にまとまる（レイアウトは §8 で確定）

### Nice-to-Have（P1）— あると体験が大きく向上

**R8. レイアウト設定（拡張機能の設定）**
- フォント、フォント色、背景色、行間などを VS Code の設定（settings.json / 設定 UI）で変更でき、生成 HTML に反映される。
- 受け入れ基準:
  - [ ] フォントファミリ / 文字色 / 背景色 / 行間を設定できる
  - [ ] 設定変更が次回生成の HTML に反映される
- （P0 の最小構成では「VS Code のテーマに近い既定スタイル固定」でも可。設定によるカスタマイズは P1 として早期に追加）

**R9. ファイル選択順の指定 / 並べ替え**
- **既定は、選択された順番に合わせて左から並べる**（2・3 ファイルとも）。
- （P1）並べ替え / 基準ファイルの入れ替えを後から行えるようにする。

**R10. コピー範囲の選択**
- 「HTML マクロ用の断片のみ」と「単体で開ける完全な HTML」を切り替えられる。

### Future Considerations（P2）— v1 では作らないが設計で考慮

- Confluence への直接ペースト / API 連携（Non-Goal を将来解禁する余地）。
- エディタ内の任意選択範囲どうしの比較、git の HEAD ⇔ 作業ツリー比較。
- 4 ファイル以上、またはタブ切り替え式の多ファイル比較。
- ダーク / ライトのテーマ出力切り替え（Confluence は白背景前提が多いため既定はライト想定）。

## 6. 想定するユーザー操作フロー

1. VS Code のエクスプローラーで比較したい 2〜3 個のファイルを選択
2. 右クリック →**「Export to Diff HTML」**を選択
3. Webview が開き、左に HTML ソース / 右にプレビューが並ぶ（選択順に左から配置）
4. 見た目を確認し、必要ならレイアウト設定を調整（P1）
5. ソースペインの「コピー」ボタンで HTML をコピー
6. Confluence ページの HTML マクロに貼り付け → 完了（ファイルは一切保存されない）

## 7. Success Metrics（成功指標）

2 つのゴールに対応させて測る。

### G1: 作業時間の短縮
- **Leading — 1 レビューあたりの差分掲載時間**: 手作業比で短縮。目標 従来の 1/2 以下。
- **Leading — コピー成功率 / エラー率**: 生成〜コピーでのエラー発生率。目標 5% 未満。
- **Leading — 社内採用率**: SQL レビューを行うエンジニアのうち本拡張を使った人の割合。目標 60%（30 日以内）。
- **Lagging — レビュー資料作成の総工数削減**（体感アンケート + 実測）。

### G2: レビュー品質の向上（正しく・もれなく）
- **Leading — 差分の網羅性**: 掲載差分に含めるべき変更が漏れなく載っているか（レビュー時の「差分に無い変更が後で発覚」件数）。目標 ほぼ 0。
- **Leading — 見やすさ満足度**: 「差分が追いやすい」への同意率（簡易アンケート / 5 段階）。目標 4.0 以上。
- **Lagging — レビュー起因の手戻り / 見逃し欠陥の減少**: 差分の見落としに起因する指摘漏れ・後工程での不具合の減少。
- **Lagging — Confluence 上の差分掲載の満足度**（社内 NPS / 簡易アンケート）。

### 測定方法
- 開発版はまず対象チームに配布し、利用ログ（起動回数・比較ファイル数）と簡易アンケートで評価。
- G2 は「差分の見落とし / 掲載漏れ」に関する定性フィードバックを重視。
- 評価タイミング: 配布 1 週間後 / 1 ヶ月後。

## 8. Decisions & Open Questions（決定事項・未解決の論点）

### 決定事項（Resolved）
- **D1（旧 Q1）3 ファイル比較の見せ方** → **3 ペイン横並び**（選択順に左から配置）。
- **D2（旧 Q3）シンタックスハイライト** → **VS Code の compare と同じ基準**で色分け・表示する。
- **D3（旧 Q4）Confluence HTML マクロ / スタイル方式** → `style` **インラインは利用可能**。**`table` ベースを基本方針**（最も安全）とし、より良い方法があれば実装時に検証する。
- **D4（旧 Q5）テーマ** → **ライトテーマ**。トーンは**ミニマルで Cool なテイスト**を志向（配色・余白は後述のデザイン方針で具体化）。
- **D5（旧 Q6）対象ファイル種別** → **任意のテキストファイルを許可**（SQL に限定しない）。
- **D6（旧 Q7）配布方法** → **社内 Git にリリース**（VSIX を**手動アップロード**）。加えて、VSIX が使いにくい環境向けに**プレーン JS をそのまま配置**できる形態も提供する。
- **D7（旧 Q2）差分アルゴリズム** → **拡張側で自前計算（依存ゼロの LCS ベース）**。理由: JS 直接配置（node_modules 不要）と相性が良い／VS Code は compare の diff 結果を安定 API で公開していない／3-way・行内差分を自前で制御できる。
- **D8 ビルド構成** → **プレーン JavaScript・ビルド不要**（バンドラ不使用）。テストは Node 標準の `node:test`。導入のしやすさ優先。
- **D9（Q8）3-way の差分表現** → **基準=左端（base）に対する差分**でハイライト。

### デザイン方針（D4 の具体化 / たたき台）
- 背景は白〜ごく淡いグレー、罫線は細く低コントラスト、角丸控えめ、等幅フォント。
- 追加=緑系・削除=赤系だが彩度を抑えたミュートトーンで「Cool」に寄せる。
- 行番号は淡いグレー。余白を広めにとり情報密度を詰めすぎない。
