# Phase 0 チケット分解 — Export to Diff HTML（VS Code 拡張 / 社内 VSIX 開発版）

**スコープ:** PRD の P0（R1〜R7）＋ D1〜D6 の確定事項。
**ゴール:** 2〜3 ファイルの差分を、`div` ルートのインライン CSS フラグメントとして生成し、VS Code 内で「左ソース / 右プレビュー」で確認・コピーできる開発版を社内配布する。
**方針:** まず S-0（差分アルゴリズム spike）で Q2 を決めてから実装に入る。

---

## マイルストーン

- **M0. 技術決定** — S-0 完了（Q2 確定）
- **M1. コア動作** — 右クリック起動 → 2 ファイル差分 → フラグメント生成 → プレビュー表示 → コピー
- **M2. 3 ファイル対応 + テーマ仕上げ** — 3 ペイン、ミニマル Cool の既定スタイル確定
- **M3. 配布** — VSIX パッケージング、社内配布、フィードバック受付開始

## チケット一覧

### S-0 【Spike】差分アルゴリズムの決定（Q2）〔✅ 完了 / 見積: M〕
- **決定:** **拡張側で自前計算（依存ゼロの LCS ベース）** を採用（PRD D7）。VS Code は compare の diff を安定 API で公開しておらず、JS 直接配置（node_modules 不要）とも相性が良い。3-way は「基準=左端」で実装（D9）。
- **成果物:** `lib/diff.js`（`diffLines` / `wordDiff` / `build2Way` / `build3Way`）＋ `test/diff.test.js`（`node:test`、8 ケース pass）。
- **付随決定:** ビルド構成は**プレーン JS・ビルド不要**（D8）。配布は**社内 Git へ手動アップロード**＋**JS 直接配置**も提供（D6）。
- **依存:** なし（完了）

### S-1 拡張のスキャフォールド / プロジェクト初期化〔見積: S〕
- **やること:** TypeScript ＋ esbuild(または webpack) で拡張の雛形作成、`package.json` の `contributes` 準備、Lint/Format、`F5` デバッグ起動確認。
- **完了条件:** 空コマンドが実行でき、開発〜デバッグのループが回る。
- **依存:** なし（S-0 と並行可）

### S-2 コンテキストメニュー登録 & 選択ファイル数の判定（R1, R7）〔見積: S〕
- **やること:**
  - エクスプローラーの右クリックに **「Export to Diff HTML」** を追加（`explorer/context`、複数選択の URI を受け取る）
  - 選択数を判定: 2 → 2-way、3 → 3-way を内部で分岐
  - 1 または 4 以上のとき、メッセージ **「2または3 個のファイルを選択してください」** を表示
- **完了条件:** 2/3 で処理が起動し、それ以外で正しくエラー表示。選択順が保持される。
- **依存:** S-1

### S-3 差分エンジン（2-way）（R2, R7）〔見積: M〕
- **やること:** S-0 の方式で 2 ファイルの行差分＋行内差分を計算し、`{左行, 右行, 状態(unchanged/added/deleted/changed), 行内ハイライト範囲}` の中間データを生成。
- **完了条件:** 追加・削除・変更・行内ハイライトが正しい中間データとして得られる（ユニットテスト付き）。
- **依存:** S-0

### S-4 差分エンジン（3-way / 3 ペイン, 基準=左端）（R7, D1, Q8）〔見積: M〕
- **やること:** 3 ファイルを行単位で整列し、左端 base に対する差分で after / reference をハイライトする中間データを生成。
- **完了条件:** サンプル2 相当の 3 ペインデータが得られる（ユニットテスト付き）。
- **依存:** S-3（中間データ構造を共有）
- **補足:** Q8（隣接ペイン差分 vs base 差分）の最終確定を含む。既定は base 基準。

### S-5 HTML フラグメント生成器（R3, D3, D4）〔見積: M〕
- **やること:** 中間データ →**`div` ルート＋`table`＋全インライン CSS** のフラグメントに変換。
  - `<!DOCTYPE>/<html>/<head>/<body>` を含めない
  - 行番号 / `+`・`−` マーカー / 左端カラーボーダー / 背景色 / 行内ハイライト
  - **背景色が剥がれても**ボーダー＋マーカーで判読できる冗長化
- **完了条件:** サンプル（`diff-fragment-confluence.html`）と同等の出力。生成物に html/body が無いことをテストで保証。
- **依存:** S-3（2-way）、S-4（3-way）

### S-6 Webview プレビュー（左ソース / 右プレビュー）（R4）〔見積: M〕
- **やること:** Webview パネルを開き、左に HTML ソース、右にレンダリング済みプレビューを 2 ペイン表示。VS Code 内で完結（外部ブラウザ不使用）。
- **完了条件:** 生成フラグメントがソース／プレビュー両方に正しく表示される。
- **依存:** S-5

### S-7 コピーボタン（R5）〔見積: S〕
- **やること:** ソースペインに**ドキュメント2枚重ねのコピーアイコン**を設置。クリックで HTML 全文をクリップボードへ。**完了フィードバックは出さない**。
- **完了条件:** 1 クリックで全文コピー。トースト等の完了表示なし。
- **依存:** S-6

### S-8 非保存の保証（R6）〔見積: S〕
- **やること:** 生成 HTML をメモリ／Webview 上のみで扱い、ワークスペースへ書き出さない実装とテスト。
- **完了条件:** 実行後にワークスペースへ新規ファイルが生成されず、`git status` に影響なし。
- **依存:** S-5

### S-9 既定テーマ仕上げ（ミニマル Cool）（D4）〔見積: S〕
- **やること:** 配色・罫線・余白・行番号色・追加/削除のミュートトーンを最終調整。ライトテーマ固定。
- **完了条件:** サンプルのトーンを基準に、社内レビューで OK。
- **依存:** S-5
- **補足:** レイアウト設定（R8 フォント/色/行間のカスタマイズ）は **Phase 1**。Phase 0 は固定既定のみ。

### S-10 エッジケース処理〔見積: S〕
- **やること:** 空ファイル / 巨大ファイル / バイナリ・非テキスト選択時の挙動、任意テキストファイル許可（D5）の確認、極端に長い行の横スクロール。
- **完了条件:** 代表エッジケースでクラッシュせず、妥当なメッセージ／表示になる。
- **依存:** S-3, S-5

### S-11 VSIX パッケージング & 社内配布（D6）〔見積: S〕
- **やること:** `vsce package` で VSIX 生成、バージョニング、社内配布手順（インストール手順書）と簡単な README、フィードバック導線を用意。
- **完了条件:** 対象チームが VSIX を入れて使える。フィードバック受付開始。
- **依存:** M2 完了（S-2〜S-10）
