## 6. 動かし方

```bash
cd agent/content-generator-api
pip install -r requirements.txt

python demo.py     # 呼び出しとレスポンスを目視（まずこれ）
pytest -v          # テスト 13 件
uvicorn app.main:app --reload --port 8000   # 実サーバ → http://127.0.0.1:8000/docs
```

**このリモート環境では `pip install` が必要**（fastapi / httpx / pytest / uvicorn は最初は入っていない）。
インストール済みなら `python3 -m pytest -q` がそのまま通る。

## 7. 次にやること（フェーズ 3 の具体案）

依頼者と合意済みの方向。着手前に「この案で進めてよいか」を一度確認するのが望ましい。

### 7-1. 状態の形

```json
{
  "jobs": {
    "job_01": {
      "status": "running",
      "topic": "新製品の紹介記事",
      "progress": {"done": 3, "total": 10},
      "chunks": ["第1章 ...", "第2章 ...", "第3章 ..."],
      "created_at": "2026-09-01T10:00:00",
      "updated_at": "2026-09-01T10:05:00"
    }
  }
}
```

`status` は `pending` / `running` / `paused` / `done` / `failed` の 5 つ。

### 7-2. 追加するエンドポイント

| メソッド | パス | 内容 |
| --- | --- | --- |
| POST | `/jobs` | 開始。ジョブを作って `running` に |
| GET | `/jobs` | 一覧 |
| GET | `/jobs/{job_id}` | 1 件の進捗 |
| POST | `/jobs/{job_id}/pause` | 中断（`running` → `paused`） |
| POST | `/jobs/{job_id}/resume` | 再開（`paused` → `running`、続きから） |
| DELETE | `/jobs/{job_id}` | 破棄 |

### 7-3. 決めておく必要があること

- **状態遷移の規則**: `done` のジョブは再開できない → **409 Conflict** を返す、など。
  遷移表を作り、それをそのままテストにする
- 存在しない `job_id` → **404**
- `job_id` の採番方法（連番か UUID か）
- 生成処理は **1 チャンクごとに状態を保存**する。そうしないと中断・再開が成立しない

### 7-4. 進め方の推奨

フェーズ 1〜2 と同じく、**実装 → `pytest` → `demo.py` を更新して目視 → 説明** の順で回す。
`demo.py` に「開始 → 中断 → 再開 → 完了」を一続きで見せるシナリオを足すと、依頼者が最も理解しやすい。

## 8. これまでの決定と、その理由

後から「なぜこうなっているのか」で迷わないための記録。**覆すときは理由を添えてここに追記すること。**

| 決定 | 理由 |
| --- | --- |
| DB を使わず JSON ファイル | 依頼者の明示的な要望。環境構築なしで動かせることを優先 |
| 保存は一時ファイル → `os.replace` | 書き込み途中で落ちても壊れた JSON が残らない（アトミックな置き換え） |
| 保存先を環境変数 `CONTENT_API_STATE_FILE` で差し替え可能に | テストが実データを汚さないため。**フェーズ 3 でも必ず維持すること** |
| `state_store.py` を分離 | `main.py` から保存の詳細を隠す。後で保存先を替えられるように |
| 検証は pydantic の `Field` に寄せる | `if` の羅列を避け、`/docs` の自動生成と仕様を一致させるため |
| `demo.py` を pytest と別に用意 | テストは通っても中身が見えない。依頼者は「動くところを見たい」ので目視用が要る |
| `demo.py` の `import` が関数の途中にある | 環境変数を設定してから `app.main` を読み込む必要があるため。**意図的な例外**。動かさないこと |
| 解説ページを HTML で用意 | Python 未経験の依頼者向け。行番号がコードと対応している |

## 9. 落とし穴・注意点

1. **zip の再生成を忘れない**
   `agent/content-generator-api.zip` は中身のコピー。ソースを変えたら必ず作り直してコミットする。
   ```bash
   cd agent && rm -f content-generator-api.zip && \
     zip -qr content-generator-api.zip content-generator-api \
       -x '*/__pycache__/*' '*/.pytest_cache/*' '*/data/*'
   ```

2. **解説ページの行番号はコードと連動していない**
   `docs/code-walkthrough.html` は `main.py`（114 行）/ `state_store.py`（68 行）/
   `demo.py`（57 行）の行番号を本文に埋め込んでいる。
   コードを編集したら、ページ側の行番号と章末のフッタ表記も直すこと。
   章構成は 01 全体像 / 02 用語 / 03 Python の記法 / 04 main.py / 05 state_store.py /
   06 demo.py / 07 出力の読み方 / 08 つまずきどころ / 09 手を動かす。

3. **解説ページの Artifact URL**
   公開済み: https://claude.ai/code/artifact/a9bc33ae-8579-42f3-a999-68c28dce648e
   **別セッションから更新する場合は、Artifact ツールに `url` としてこの URL を渡すこと。**
   渡さずに publish すると、別の新しいページが作られてしまう。

4. **ブランチ**
   `claude/fastapi-sample-api-ez35y6` 以外に push しない。`git push -u origin claude/fastapi-sample-api-ez35y6`。
   **PR は依頼者が明示的に求めたときだけ作る**（現時点では未作成、依頼もされていない）。

5. **`data/state.json` はコミットしない**（`.gitignore` 済み）。実行時に自動生成される。

6. **同時書き込み**
   現状の Lock は 1 プロセス内のみ。複数ワーカーで動かす想定が出てきたら、この前提が崩れることに注意。
