FastAPI サンプル・第一歩

main.py と demo.py の読み方

Python をこれから触る人のための、2 ファイルの逐次解説。app/main.py は「API を用意する側」、demo.py は「その API を呼ぶ側」です。この 2 つの関係が分かれば、あとの拡張はほとんど同じ形の繰り返しになります。

01全体像 — 2 つのファイルの役割

まず「どちらが店で、どちらが客か」だけ掴む

この 2 ファイルは、まったく違う仕事をしています。混ざると分からなくなるので、最初にここだけ分けておきます。

呼ばれる側

app/main.py

API の本体。「こういう住所（URL）に、こういう内容が来たら、こう返す」という取り決めを並べたファイル。自分から動き出すことはなく、呼ばれるのを待っています。

呼ぶ側

demo.py

その API を実際に叩いて、返ってきたものを画面に表示するスクリプト。python demo.py と打つと上から順に実行されます。

ここが要点

main.py の中の関数は、あなたが呼び出すコードをどこにも書いていません。「/health に GET が来たらこの関数を呼ぶ」とだけ登録しておき、実際に呼ぶのは FastAPI です。この「登録しておいて、あとは任せる」形が、最初いちばん戸惑うところです。

02先に言葉を 6 つだけ

コードの前に、出てくる用語をまとめて片付ける

APIApplication Programming Interface
プログラムから使える窓口。人間向けの画面の代わりに、機械が読みやすい形（JSON）でやりとりします。
エンドポイントendpoint
窓口ひとつひとつの住所。/health や /echo がそれ。このサンプルには 6 つあります。
リクエスト / レスポンスrequest / response
「送るもの」と「返ってくるもの」。必ずこの往復 1 セットで動きます。
GET / POSTHTTP メソッド
GET は「読むだけ」、POST は「何かを送って、変えてもらう」。同じ住所でも、この 2 つは別の窓口として扱われます。
JSONデータの書き方
{"status": "ok"} のような形式。Python の辞書（後述）とほぼ同じ見た目で、相互に変換できます。
ステータスコードstatus code
結果を表す 3 桁の数字。200＝成功、422＝送った内容がおかしい、404＝そんな住所はない、500＝サーバ側で例外が起きた。

03Python の記法を 8 つだけ

この 2 ファイルを読むのに必要なぶんだけ。文法書は要りません

import json                      # 1) 他の人が書いた道具を持ってくる

def show(res):                    # 2) 関数の定義。res は受け取る値の名前
    print(res)                    #    インデント（字下げ）が中身の範囲

@app.get("/health")               # 3) デコレータ。すぐ下の関数に印をつける
def health() -> dict[str, str]:   # 4) -> は「返すものの型」のメモ書き
    return {"status": "ok"}       # 5) {} は辞書。キー: 値 の対応表

class EchoRequest(BaseModel):     # 6) データの形を決める「型」を作る
    message: str

name = "audeo"
print(f"やあ、{name}。")            # 7) f"..." の {} に変数が埋め込まれる

with open("a.txt") as f:          # 8) 使い終わったら自動で片付ける書き方
    print(f.read())
import

他のファイルやライブラリの機能を持ち込む宣言。from fastapi import FastAPI は「fastapi の中の FastAPI だけ持ってくる」という意味です。

def 名前(引数):

関数（ひとまとまりの処理）を作ります。Python は字下げで範囲を表すのが最大の特徴で、他言語の { } に当たります。ズレるとエラーになります。

@app.get(...)

「デコレータ」。直後の関数に機能を追加したり、目印を付けたりします。ここでは FastAPI に「この住所はこの関数が担当」と登録する役目。今回いちばん重要な記法です。

-> dict[str, str]

型ヒント。「文字列をキー・文字列を値とする辞書を返す」というメモです。Python は実行時にこれを強制しませんが、FastAPI はこの情報を読み取って動作を変えるので、書く意味があります。

{"status": "ok"}

辞書（dict）。キー: 値 の対応表で、JSON とほぼ同じ形。関数がこれを返すと、FastAPI が JSON に変換して送り返します。

class 名前(BaseModel):

クラス＝自前のデータ型。(BaseModel) は「BaseModel の性質を受け継ぐ」という意味で、これだけで検証機能が付いてきます。

f"...{name}..."

f-string。文字列の中の { } に変数の中身が差し込まれます。

with ... as f:

後片付けを自動化する書き方。ファイルなら閉じ忘れが起きません。demo.py で 3 回登場します。

04app/main.py を読む

上から 5 つのかたまりに分けて読みます

4-1. 準備（1〜27 行目）

app/main.py 16〜27 行目準備
from __future__ import annotations

from fastapi import FastAPI
from pydantic import BaseModel, Field

from app import state_store

app = FastAPI(
    title="Content Generator API (sample)",
    description="FastAPI と TestClient の動作確認用サンプル。",
    version="0.1.0",
)
from __future__ import annotations

古い Python でも新しい型の書き方（dict[str, str] など）を使えるようにするおまじない。意味は分からなくて構いません。ファイルの先頭に置く決まりです。

from app import state_store

同じフォルダの state_store.py（JSON ファイルへの読み書き担当）を持ち込みます。役割ごとにファイルを分けておくと、後で保存先を DB に替えるときも、この 1 ファイルだけ直せば済みます。

app = FastAPI(...)

アプリ本体を 1 個作ります。この app という変数が、以降すべての中心です。title などは /docs の画面に表示される情報。

4-2. 受け渡すデータの形を決める（39〜62 行目）

app/main.py 39〜50 行目スキーマ
class EchoRequest(BaseModel):
    message: str = Field(..., min_length=1, description="送りたい文字列")
    repeat: int = Field(1, ge=1, le=5, description="繰り返す回数（1〜5）")


class EchoResponse(BaseModel):
    message: str
    length: int
message: str

「message という項目があり、それは文字列」という宣言。数値や欠落が来たら、関数が動く前に弾かれます。

Field(..., min_length=1)

第 1 引数の ...（3 つの点。Python では省略記号そのものが値です）は「初期値なし＝必須」という意味。min_length=1 で空文字も禁止しています。

Field(1, ge=1, le=5)

初期値 1、ge＝1 以上（greater or equal）、le＝5 以下（less or equal）。この 1 行だけで検証が完成します。if 文は一切書きません。

class EchoResponse

返す側の形。決めておくと、うっかり余計な情報（内部の値など）が漏れて返ることを防げます。

なぜクラスを 4 つも作るのか

この形（スキーマ）を書いておくと、①入力の検証 ②レスポンスの形の固定 ③/docs の自動生成 の 3 つが同時に手に入ります。手書きの if で検証するより短く、しかも仕様書が自動で最新になります。

4-3. いちばん簡単なエンドポイント（68〜71 行目）

app/main.py 68〜71 行目GET /health
@app.get("/health", summary="疎通確認")
def health() -> dict[str, str]:
    """サーバが起きているかを返すだけのエンドポイント。"""
    return {"status": "ok"}
@app.get("/health")

これが API の 1 行目にして核心です。「/health に GET が来たら、下の関数を呼べ」と app に登録しています。@app.post(...) にすれば POST 用になります。

def health()

関数名は自由（URL とは無関係）。引数が無いので、この窓口は何も受け取りません。

"""..."""

三重引用符の文字列＝説明文（docstring）。FastAPI はこれを読んで /docs の説明欄に出します。書けば書くほど画面が親切になります。

return {"status": "ok"}

辞書を返すだけで、FastAPI が {"status":"ok"} という JSON に変換し、ステータス 200 を付けて送り返します。

4-4. 値を受け取る 2 つの方法（74〜92 行目）

app/main.py 74〜92 行目GET /greet ・ POST /echo
@app.get("/greet/{name}", summary="パスパラメータの例")
def greet(name: str, polite: bool = False) -> dict[str, str]:
    greeting = f"はじめまして、{name} さん。" if polite else f"やあ、{name}。"
    return {"greeting": greeting}


@app.post("/echo", response_model=EchoResponse, summary="リクエスト本文の例")
def echo(req: EchoRequest) -> EchoResponse:
    message = req.message * req.repeat
    return EchoResponse(message=message, length=len(message))
"/greet/{name}"

URL の {name} の部分が、そのまま関数の引数 name に入ります（パスパラメータ）。/greet/audeo なら name = "audeo"。

polite: bool = False

URL に無い名前で、かつ初期値がある引数はクエリパラメータ扱い。/greet/audeo?polite=true で True になります。置き場所（URL の一部か、? の後ろか）を FastAPI が自動で見分けています。

A if 条件 else B

Python の三項演算子。「条件が真なら A、偽なら B」。英語の語順で読むと自然です。

req: EchoRequest

型が BaseModel のクラスの場合、FastAPI はリクエストの本文（body）として受け取ります。届いた JSON が形に合わなければ、この関数はそもそも呼ばれず422 が返ります。

req.message * req.repeat

Python では文字列 × 数値で繰り返しになります。"ping" * 3 → "pingpingping"。

response_model=EchoResponse

返す形の指定。ここに書いた項目だけが外に出ます。

4-5. 状態を読み書きする 3 つ（95〜114 行目）

app/main.py 95〜108 行目GET /state ・ POST /state/increment ・ POST /state/reset
@app.get("/state", response_model=StateResponse, summary="現在の状態を読む")
def read_state() -> StateResponse:
    return StateResponse(**state_store.load_state())


@app.post("/state/increment", response_model=StateResponse, summary="状態を更新する")
def increment(req: IncrementRequest | None = None) -> StateResponse:
    step = req.step if req else 1
    return StateResponse(**state_store.increment_counter(step))
state_store.load_state()

別ファイルの関数を呼んで、data/state.json の中身を辞書として受け取ります。main.py 自身はファイルの扱いを一切知りません——この分担が後で効いてきます。

StateResponse(**辞書)

** は辞書を「バラして引数にする」記号。{"counter": 6} は StateResponse(counter=6) と書いたのと同じになります。

req: IncrementRequest | None = None

| は「または」。本文があってもなくても受け付けるという意味で、これにより POST /state/increment を本文なしで呼べます（その場合 step は 1）。

step = req.step if req else 1

本文が無かった（req が None）ときの保険。Python では None は偽として扱われます。

ゴールへの橋渡し

このあと作る「開始 / 中断 / 再開」も、まったく同じ形です。counter という状態が jobs（ジョブごとの status と進捗）に変わり、/state/increment が /jobs/{id}/pause に変わるだけ。仕組みは 1 ミリも変わりません。

05demo.py を読む

こちらは上から順に実行される、普通のスクリプトです

5-1. 表示用の小さな関数（18〜21 行目）

demo.py 18〜21 行目show()
def show(res) -> None:
    """1 回の呼び出しの結果を見やすく表示する。"""
    body = json.dumps(res.json(), ensure_ascii=False)
    print(f"  {res.request.method:6} {res.request.url.path:20} -> {res.status_code}  {body}")
res.json()

返ってきた JSON を Python の辞書に変換します。

json.dumps(..., ensure_ascii=False)

辞書を文字列に戻します。ensure_ascii=False を付けないと日本語が や のような記号列になります。日本語を扱うときの定番の指定です。

{res.request.method:6}

f-string の書式指定。:6 は「6 文字分の幅で左詰め」。これで各行の -> の位置が縦に揃います。

-> None

「何も返さない」という型ヒント。表示するだけの関数なので値は返りません。

5-2. 実行の準備（24〜31 行目）

demo.py 24〜31 行目main() の冒頭
def main() -> None:
    # 状態ファイルは一時ディレクトリへ。何度実行しても 0 から始まる。
    with tempfile.TemporaryDirectory() as tmp:
        os.environ["CONTENT_API_STATE_FILE"] = os.path.join(tmp, "state.json")

        from app.main import app  # 環境変数を設定してから import する

        with TestClient(app) as client:
tempfile.TemporaryDirectory()

使い捨てのフォルダを作り、with を抜けるときに中身ごと自動で消します。デモが本物の data/state.json を汚さないための配慮です。

os.environ["..."] = ...

環境変数の設定。state_store.py はこの値があればそちらのファイルを使うようになっています。コードを書き換えずに保存先を差し替える常套手段です。

from app.main import app

この import がファイル先頭ではなく関数の途中にあるのは、わざとです。先に環境変数を設定してから読み込む必要があるため、この順序が崩れると保存先の切り替えが効きません。普段は import を先頭に書いてください——これは例外的な書き方です。

with TestClient(app) as client

アプリを操作するクライアントを用意します。uvicorn などのサーバは起動しません。ネットワークを通さず、直接 app を呼ぶ仕組みです（だから速く、ポートの空き状況にも左右されません）。

5-3. 実際に呼ぶ（32〜45 行目）

demo.py 32〜45 行目呼び出し
            show(client.get("/health"))
            show(client.get("/greet/audeo", params={"polite": True}))
            show(client.post("/echo", json={"message": "ping", "repeat": 3}))

            show(client.post("/echo", json={"message": "ping", "repeat": 99}))

            show(client.get("/state"))
            show(client.post("/state/increment"))
            show(client.post("/state/increment", json={"step": 5}))
client.get("/health")

GET リクエストを 1 回送り、レスポンスを受け取ります。この 1 行が main.py の health() を呼んでいます。

params={"polite": True}

URL の ? 以降（クエリパラメータ）になります。実際に送られるのは /greet/audeo?polite=true。

json={"message": "ping", ...}

リクエストの本文として JSON を送ります。この辞書が EchoRequest の検査を通り、req として関数に渡ります。

"repeat": 99

わざと上限（5）を超えた値。ここだけ 422 が返ることを見せるための行です。echo() 関数は呼ばれません。

client.post("/state/increment")

json= を書いていないので本文なし。IncrementRequest | None にしてあるおかげでエラーにならず、step は初期値 1 になります。

5-4. 状態が残ることの確認（47〜57 行目）

demo.py 47〜57 行目締めくくり
        with TestClient(app) as fresh_client:
            show(fresh_client.get("/state"))

        print("\n[5] 実際に書かれているファイルの中身")
        with open(os.environ["CONTENT_API_STATE_FILE"], encoding="utf-8") as f:

クライアントを作り直しても値が 6 のままなのが、この行の見どころ。状態がメモリではなくファイルにあることの証明で、実運用では「サーバを再起動しても消えない」に相当します。

文字コードの明示。特に Windows では、これを省くと日本語が文字化けします。ファイルを開くときは常に付ける習慣を。

Python の定型句。「このファイルを直接実行したときだけ中を動かす」という意味です。他のファイルから import されたときは動きません。main() という関数名は慣習で、特別な意味はありません。

06出力の読み方

python demo.py の実際の結果

$ python demo.py
[1] 基本のエンドポイント
  GET    /health              -> 200  {"status": "ok"}
  GET    /greet/audeo         -> 200  {"greeting": "やあ、audeo。"}
  GET    /greet/audeo         -> 200  {"greeting": "はじめまして、audeo さん。"}
  POST   /echo                -> 200  {"message": "pingpingping", "length": 12}

[2] 入力が不正なとき（FastAPI が自動で 422 を返す）
  POST   /echo                -> 422  {"detail": [{"type": "less_than_equal", ...}]}

[3] JSON ファイルで持つ状態
  GET    /state               -> 200  {"counter": 0}
  POST   /state/increment     -> 200  {"counter": 1}
  POST   /state/increment     -> 200  {"counter": 6}
  GET    /state               -> 200  {"counter": 6}

[4] クライアントを作り直しても状態は残る
  GET    /state               -> 200  {"counter": 6}
行見るべきところ
2 行目と 3 行目URL の表示は同じですが、3 行目は ?polite=true 付き。show() がパス部分しか出さないためで、返る文章が違うことで区別できます。
POST /echo → 200"ping" が 3 回繰り返されて 12 文字。length は main.py が計算した値です。
POST /echo → 422この行だけ、あなたの書いた関数は 1 行も動いていません。FastAPI が入口で弾き、どの項目がなぜ駄目かを detail に入れて返しています。
counter: 1 → 61 回目は本文なしで +1、2 回目は step: 5 で +5。合計 6。
[4] の 6新しいクライアントでも 6。ファイルに書かれているからです。

07つまずきやすいところ

最初に必ず出会うものを先に

ModuleNotFoundError: No module named 'app' と出る

実行している場所が違います。content-generator-api フォルダの直下で python demo.py を実行してください。Python は「今いる場所」を基準に app/ を探します。

IndentationError と出る

字下げのズレです。Python では字下げが構文そのもの。タブと半角スペースの混在が原因のことが多いので、スペース 4 個に統一してください。

422 は「バグ」ですか？

いいえ、設計どおりの正しい動作です。「送られた内容が決めた形に合っていない」と API が正しく指摘した状態。500（サーバ側の想定外エラー）とは意味がまったく違います。

uvicorn で起動するのと demo.py は何が違う？

uvicorn は本物のサーバを立ち上げ、ブラウザや他の PC から http://127.0.0.1:8000 でアクセスできるようにします。demo.py（TestClient）はサーバを立てず、同じプロセスの中で直接 app を呼びます。

呼ばれる main.py 側のコードは、どちらでも完全に同じです。だからテストで確かめた動作は、本番でもそのまま通用します。

counter が 0 に戻らない / 変な値になった

POST /state/reset を呼ぶか、data/state.json を削除してください。次回アクセス時に初期値から作り直されます。なお demo.py は毎回一時フォルダを使うので、常に 0 から始まります。

関数名と URL は揃えるべき？

揃える必要はありません。結び付けているのは @app.get("/health") の行だけで、関数名は人間が読むためのものです。ただし揃えておくと探しやすくなります。

08手を動かして確かめる

読むより 1 回いじるほうが早く分かります

  1. まず /docs を開くuvicorn app.main:app --reload --port 8000 を実行し、ブラウザで http://127.0.0.1:8000/docs へ。書いた docstring や Field の説明がそのまま画面になっているのが分かります。その場で API を試せます。
  2. 挨拶の文面を変えるmain.py の greet() の中の文字列を書き換えて、python demo.py を再実行。変更が出力に出れば、どこが何に対応しているか腑に落ちます。
  3. 上限を 5 から 10 に変えるrepeat の le=5 を le=10 に。demo.py の 422 の行が 200 に変わります（repeat: 99 はまだ超過なので、le=100 まで上げると変化します）。
  4. エンドポイントを 1 つ足す既存の 4 行をコピーして、@app.get("/ping") と def ping() に。demo.py に show(client.get("/ping")) を 1 行足して確認します。
  5. state.json を直接開くPOST /state/increment を何度か呼んだあと data/state.json をエディタで開いてみてください。「DB を使わず状態を持つ」の正体がただのテキストファイルだと分かります。
