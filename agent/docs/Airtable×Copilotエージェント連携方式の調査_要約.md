# Airtable × Copilotエージェント連携方式の調査 - 要約

- **作成日**：2026-09-27
- **目的**：Airtableの配信カード業務にCopilotエージェントを連携させるための実装方式を、ユースケース別に整理

---

## 核となる前提

| 項目 | 方針 |
|---|---|
| AIの回答の扱い | **下書き**として扱う（確定ではない） |
| 書き込み | 下書き用の欄に可能 |
| 確定操作 | **人が行う**（エージェントには任せない） |
| 画面構成 | ステータス欄で状態管理（起案待ち → 起案中 → 下書きあり → 修正依頼中 → 確定） |

---

## Copilotの2つの種類

| 観点 | Agent Builder | Copilot Studio |
|---|---|---|
| **外部システムへの書き込み** | ❌ できない | ✅ できる |
| **自動起動** | ❌ できない | ✅ できる（イベントトリガー） |
| **追加費用** | なし | あり（Copilotクレジット） |
| **主な用途** | Q&A・文章生成 | 外部システム操作・ワークフロー |

→ **自動書き込み・自動起動を伴う方式は Copilot Studio が前提**

---

## 17個の連携パターン（難易度順）

### レベル0：手作業

| ID | パターン | トリガー | 特徴 |
|---|---|---|---|
| **P1** | チャットで生成し、人が転記 | 手動 | 追加開発なし。転記の手間あり |
| **P2** | CSVで渡してCSVで受け取り、Airtableにインポート | 手動 | 複数カード一括処理可能 |

### レベル1：ファイル経由

| ID | パターン | インターフェース | 難易度 |
|---|---|---|---|
| **P3** | SharePointにファイルを置き、Power AutomateがAirtableに書き込む | ファイル＋API | ★★ |
| **P4** | Sync APIで同期テーブルに取り込む | Sync API | ★★ |

### レベル2：M365側から書き込む（人が起動）

| ID | パターン | 特徴 |
|---|---|---|
| **P5** | エージェントに依頼し、エージェント自身がAirtableに書き込む | 対話の中で修正・確認できる |
| **P6** | P5でAirtable公式MCPサーバーを使う | カスタムコネクタ不要 |

### レベル3：自動起動（M365が主導）

| ID | パターン | 起動方法 | 長所 |
|---|---|---|---|
| **P7** | Power Automateが定期実行し、未起案のカードを起案 | 定期実行（例：15分ごと） | 外部受け口を公開しない |
| **P8** | P7 + Teams承認を挟む | 定期実行 + 承認 | 人の確認を必ず挟める |

### レベル4：自動起動（Airtable が主導）

| ID | パターン | トリガー | 即時性 |
|---|---|---|---|
| **P9** | Airtableのボタン → Power Automate → エージェント | ボタン/オートメーション | 数十秒～数分 |
| **P10** | Airtable → Copilot Studio自律エージェント | イベントトリガー | 高い |
| **P11** | AirtableのスクリプトからDirect Lineで直接呼び出し | スクリプト実行 | 高い（30秒制限あり） |
| **P12** | Webhooks APIで変更を通知 | Webhook | やや低い |
| **P13** | iPaaS（Make・Zapierなど）経由 | iPaaS検知 | 数分 |

### レベル5：修正ループ付き

| ID | パターン | UI | 特徴 |
|---|---|---|---|
| **P14** | Airtable上の「修正指示」欄と再実行ボタン | Airtable画面内 | 画面だけで完結 |
| **P15** | Teams のアダプティブカードで確認・修正 | Teams | 簡単な指示向き |
| **P16** | 専用画面（code appsなど）で対話・修正 | 専用画面（別タブ） | 柔軟な操作が可能 |
| **P17** | Airtable画面内に拡張機能で修正パネル | Airtable拡張機能 | 画面を離れずに修正（ベータ版） |

---

## 修正指示のUI方式（Airtableを作業の起点にする場合）

| # | 方法 | 画面 | 対話性 | 実装量 | 主な制約 |
|---|---|---|---|---|---|
| **U1** | Airtableのボタン + 修正指示欄 | Airtable | 低い | 小 | 反映に数十秒待機 |
| **U2** | Airtable画面内の拡張機能パネル | Airtable | 高い | 大 | SDKがベータ版 |
| **U3a** | 別タブでエージェントのチャット画面 | チャット | 中～高 | 中 | 文字のやり取りのみ |
| **U3b** | 別タブで専用画面（code apps） | 専用画面 | 高い | 大 | 画面開発・保守が必要 |
| **U4** | Teams で確認・修正指示 | Teams | 中 | 中 | 作業起点から離れる |

## 段階的な進め方の例

| 例 | 経路 | 考え方 |
|---|---|---|
| **例1** | P1 → P5/P6 → P7 → P14 | M365起点。受け口を公開せずに手動から自動へ |
| **例2** | P1 → P9 → P14 | Airtable起点。即時性を重視 |
| **例3** | P1 → P7 → P8 → P15 | 人の確認を必ず挟み、Teams で完結 |
| **例4** | P1 → P5 → P16 | 修正のやり取りを専用画面で行う |
| **例5** | P7/P9 → U1（軽い修正）+ U3a/U3b（込み入った修正） | 重さで使い分け |

## 共通で用意しておくとよいもの

- ✅ Airtableのステータス欄（起案待ち → 起案中 → 下書きあり → 確定）
- ✅ 下書き用の欄（確定欄とは分ける）
- ✅ エージェントの出力形式の固定（JSON など）
- ✅ 書き込み前の形式チェック
- ✅ 失敗時の通知と再実行の手順

---

## 確認が必要な事項

### 情シス側
- [ ] Power Automate のHTTPトリガー「Anyone」設定
- [ ] DLPポリシーでHTTPアクション・カスタムコネクタ許可
- [ ] Copilot Studio ライセンスと MCP接続
- [ ] 自律エージェント（イベントトリガー）許可
- [ ] Copilot クレジット契約量

### Airtable管理者
- [ ] 契約プラン（Sync API は Business/Enterprise のみ）
- [ ] PAT の発行と権限管理
- [ ] 公式MCPサーバーの許可リスト設定

### 業務側
- [ ] 即時性の要件（数分の遅れで困るか）
- [ ] AI回答の扱い（✅ 下書き、確定は人）
- [ ] 修正指示の出し方（Airtable / Teams / 専用画面）
- [ ] Interface Extensions（ベータ版）の使用可否
