# 機能説明(資料作成用)

「配信コンテンツプランナー」の機能を、**正しく**説明するための情報。PowerPoint などの資料を作る人(エージェント)は、この内容に沿って書くこと。
画面の用語は、実際の画面の表記(日本語 / English)に合わせてある。**「未実装・制限」の章に書いたことは、できると書かない。**

---

## 1. 一言で

メール・プッシュの**配信コンテンツ**(テーマ、メイン画像、ヘッドライン・コピー、セクションごとの商品、制作指示)を、**AI の提案を選びながら**企画するアプリ。
カレンダーで配信を管理し、配信カードの中で、AI と相談しながら、プレビューを見て仕上げる。US チームと JP チームが、日本語・英語のどちらでも使える。

## 2. 解決する課題と、価値

| 課題 | このアプリでの解決 |
|---|---|
| 企画の素案づくりに時間がかかる | 「すべてAIで下書き」で、テーマから制作指示まで、一度に下書きを作る |
| 商品の選定が属人的 | 在庫・売上トレンド・評価・季節・天候などを踏まえた AI の選定と、**その理由**を表示する |
| 国ごとに、商品・言語が違う | 配信カードの「国」(US / JP)に合わせて、商品・画像・コピーの言語を使い分ける |
| デザイナーが、商品情報を探し回る | 商品情報ペインで、掲載商品の情報を一覧し、売上・在庫の推移や MD の方針も見られる |
| メールの構成を、毎回、作り直す | テンプレート(構成の型)を選ぶ。自分でも作って、チームで共有できる |
| AI の案が、気に入らない | チャットで指示を足して、案を作り直す(「この商品を必ず入れて」など) |

**人が決める、AI は提案する**、という立場。AI の案は、**採用するまで反映されない**(一部は、反映して「元に戻す」で戻せる)。

## 3. 想定する利用者

- **企画担当(販促・CRM・EC)**: 配信を企画し、AI の案を選んで、内容を決める。
- **デザイナー・制作担当**: 決まった内容(ヘッドライン、コピー、商品、制作指示)と商品情報を見て、制作する。
- **MD(商品担当)**: 商品の販売方針・販促計画を、AI の選定と制作の判断に使えるようにする(データとして登録されている)。
- 国: **US チーム / JP チーム**。外部ユーザー(ゲスト)にも見せられる。

## 4. 画面の流れ

### 4.1 配信カレンダー(最初の画面)
- 月表示のカレンダーに、配信カードが並ぶ。カードは、時刻と名前の帯で表示し、**ステータスの色**(左の線と薄い色)で状態が分かる。
- **日付のマスを押すと、その日の 10:00 を配信日時にして、新規作成が開く**(マウスを乗せると「＋」が出る。過去の日付でも作れる)。国・チャネル・部署で絞り込んでいれば、その値も最初から入る(ヘッダーの「新規作成」も同じ)。
- ステータス(4段階・色分け): **未起案 → 検討中 → 承認済み → 確定**。
- 絞り込み: **国 / チャネル / 部署 / ステータス**。件数が表示される。月の移動ができる。
- 国: US / JP。チャネル: **メール / プッシュ**。部署: **販促 / CRM / EC**。
- ヘッダー:「配信カレンダー」、**テンプレート**ボタン、言語の切り替え(**日本語 | English**)、「**開いたとき自動で下書き**:オン/オフ」のスイッチ、「**新規作成**」。
- カードを押すと、配信カードの編集画面が開く。

### 4.2 配信カードの編集画面(ダイアログ)
**4つのペイン**で構成する。ペインの境界はドラッグで幅を変えられる(幅は保存される)。

| ペイン | 内容 |
|---|---|
| ① 左: 配信情報 | 青い大きなボタン「**すべてAIで下書き**」。配信名、配信日時、国、チャネル、部署、ステータス。「工程」として、テーマ・ヘッドライン・コピー・制作指示(それぞれ、AI の理由・切り口つき)。右上に、進み具合のチップ「**工程 n / 5**」 |
| ② 中: コンテンツ生成 | 5つのタブ(テーマ / テンプレート / ヒーロー / セクション / 制作指示)。下半分に、**AIチャット** |
| ③ 右: プレビュー | メール / プッシュのプレビュー。倍率の変更(スライダー、「全体」ボタン) |
| ④ 右端: 商品情報 | 掲載商品の参照用の一覧。**既定では折りたたまれている**(右端の細い帯「商品情報」を押すと開く) |

- 画面を閉じるときの操作: 「保存」「キャンセル」。
- **AI の案は、保存しない**(画面を開いている間だけ)。保存されるのは、採用した内容と、その補足(理由・切り口)。

## 5. 機能の詳細

### 5.1 すべてAIで下書き
- 左ペイン上部のボタン。**テーマ → テンプレート + メイン画像 → ヘッドライン・コピー → 各セクション(見出し・コピー・商品)→ 制作指示**の順に、AI の第1候補で、下書きを作る。
- 進み具合が、全画面の「AIが下書きを作っています」で表示される(「スキップして開く」で中断できる)。
- 結果は、**画面に反映するだけで、保存はしない**。気に入らなければ、保存せずに閉じられる。
- 1回で、AI を **6〜9回**呼ぶ(セクションの数による。所要時間は、数十秒程度)。
- 前提: 配信日時が入っていること。
- **自動下書き**: ヘッダーのスイッチがオンのとき、**テーマも商品も空のカードを開く**と、自動で下書きを始める(同じカードで1回だけ)。

### 5.2 ① テーマ(配信全体の前提。メールには出ない)
- 「AIで案を出す」で、テーマの案を **3つ**出す(各案に、理由つき)。
- 案から「採用」を押すと、「現在のテーマ」に入る。採用中の案の**理由**(「AIの理由」)は、保存され、あとで見られる。
- 手で書き換えると、理由は消える(文と理由が食い違わないように)。

### 5.3 ② テンプレート(メールの構成の型)
- 一覧から選ぶ。選ぶと、③④のセクションの構成が変わる。
- **標準のテンプレート 10種**:
  | 名前 | 構成 |
  |---|---|
  | 自由(カテゴリ見出しを自動) | 商品の数に決まりがない |
  | Standard Hero + 4 Grid Items | メイン画像 + 2×2 の商品 4点 |
  | Collaboration Hero + 2 Features + 2 Grid | コラボ用ヒーロー + 特集 2点 + グリッド 2点 |
  | Price: Limited Offer & Value Hero | 赤基調のヒーロー + 価格を強調した 4点 |
  | Standard Hero + 2 Category | カテゴリ 2つ(各 2点)。カテゴリごとに見出し |
  | Standard Hero + 3 Category | カテゴリ 3つ(各 2点)。カテゴリごとに見出し |
  | セール(大きく 1 点 + グリッド) | お知らせ帯 + 文字を大きく重ねたヒーロー。大きく 1 点とグリッドを交互に、最後に写真だけのタイル(12点) |
  | 特集(モザイク + グリッド) | 大 1 点 + 小 2 点のモザイク + 見出し付きグリッド(7点) |
  | ストーリー(写真 + 文) | 写真と商品の説明を左右交互 + 見出し付きグリッド(7点) |
  | コレクション(大きな写真中心) | 大きな写真・モザイク・3 列グリッド(11点) |
- **セクションの部品**(テンプレートを作るとき): グリッド(2 / 3 列)、写真だけ(2 / 3 列)、大きく(全幅)、モザイク(左が大 / 右が大)、ストーリー、特集。どれにも、見出しと、セクションの後のボタン(1〜2 個)を付けられる。ヒーローは、ヘッドラインの見せ方(帯で重ねる / 大きく重ねる / 写真の下)、ボタンの数、お知らせ帯を選べる。
- 構成のプレビューは、メールに近い縦長の見取り図で表示する。
- 「テンプレートを管理(作成・編集)」から、管理画面を開ける。
- AI も、テーマや時期から、**テンプレートを選べる**(「すべてAIで下書き」のとき)。

### 5.4 ③ ヒーロー(メイン画像 / ヘッドライン・コピー)
- **メイン画像**: 登録済みの画像(JP 20点、US 20点)から、AI がテーマ・季節・用途・タグに合う画像を選ぶ。選定理由つき。候補が3件まで出る。「元に戻す」で戻せる。一覧から手で選ぶ、ドラッグ&ドロップでプレビューに置く、もできる。画像は、国(JP / US)に合うものだけが対象。
- **ヘッドライン・コピー**: 「ヘッドライン」(メイン画像の上に載る大見出し)と「コピー」(その下の導入文)を、**組で** 3案出す(各案に「切り口」つき)。言語は「国に合わせる / 日本語 / English」から選べる(国に合わせる = US は英語、JP は日本語)。「採用」で、両方が反映される。
- プレビューでは、ヘッドラインが**自動で縮小して、1行に収まる**。

### 5.5 ④ セクション(見出し・コピー・商品)
- テンプレートのセクションごとに、**サブタブ**がある(例: グリッド / 特集 / セクション1 …)。
- 各セクションは、3つのブロック: **① 見出し(切り口)**(カテゴリ系のテンプレートのみ)/ **② コピー** / **③ 商品**。
- 「**このセクションをまとめてAIで選定**」で、見出し・コピー・商品を一度に選ぶ。各ブロックにも、「作り直す」「選び直す」がある。
- **商品の選定**: AI が、在庫(少ないものは避ける)、売上トレンド、評価、季節、天候、テーマ、メイン画像・ヘッドラインとの整合などから選び、**理由**を表示する。選定済みの商品と、「残りの候補」(最大3件)が出る。
- 商品の操作(このタブだけで行う): 並べ替え(矢印、ドラッグ)、「外す」(候補へ戻る)、候補の「選ぶ」、理由の編集、**すべての商品から探す**(検索。検索語かカテゴリを指定すると、商品が出る。20件ずつ表示)。
- 商品は、配信カードの**国に合う市場(JP / US)のものだけ**が、AI の対象と検索の対象になる。
- AI の選定結果は、そのまま反映され、「**元に戻す**」で復元できる。

### 5.6 ⑤ 制作指示
- 制作担当に渡す指示文の案を **3つ**出す(各案に、方針の「切り口」つき)。目安は、日本語で200〜240文字。
- 採用すると、左ペインにも反映される。理由・切り口は、保存される。

### 5.7 AIチャット(中ペインの下半分)
- **開いているタブ**の案づくりに、**ユーザーの指示を加える**ためのチャット(「AIチャット — ○○」)。
- 使い方の例: 「もっとカジュアルに」「レインブーツを必ず入れて」「もっと手頃な価格の商品で」「新作を優先して」。入力欄の近くに、**よく使う頼み方**のボタンが出る。
- 動作: 指示を送ると、そのタブの案(または、メイン画像・セクションの選定)が、**指示を反映して作り直される**。AI は、どう直したかを一言で返す。前の指示の条件(「必ず含める」など)は、会話の中で引き継ぐ。
- **質問・相談**(「この商品ラインアップはどう思う?」)のときは、**案を変えずに、答えだけ**を返す。返答の言語は、ユーザーの発言に合わせる。
- 会話は、**タブごと**。画面を開いている間だけ保持する(保存しない)。
- 高さは、上端のつまみのドラッグで変えられる。折りたたみもできる。
- 対象外: **テンプレート**のタブ。

### 5.8 プレビュー(メール / プッシュ)
- **メール**: ヒーロー(メイン画像 + ヘッドライン + コピー)、セクションごとの見出し・コピー・商品タイル(画像、名前、価格、ボタン)。テンプレートの構成に従う。
- **プッシュ**: 通知の見た目(iOS / Android の切り替え)。「タップ後のメッセージ」も確認できる。
- **直接編集**: プレビューの上で、セクションの見出しとコピーを書き換えられる。商品のドラッグで並べ替え、ホバーで「前へ / 後へ / 削除」。
- **倍率**: スライダーと、「全体」ボタン(押すと全体が収まる倍率。もう一度押すと **100%** に戻る)。
- 価格の表記: JP の商品は円(¥)、US の商品はドル($)。

### 5.9 商品情報ペイン(参照専用。操作しない)
- 掲載商品を、**メールの並び順**に、セクションごとに一覧する。1行は、画像、名前、「コード・価格・在庫」、売上トレンドの矢印(↑ ↓ →)。**在庫が少ない商品には「残少」**の印。
- 行にマウスを置くと、プレビューの**該当商品が枠で光る**。
- 行を押すと、**詳細のフロート**が開く(位置は固定):
  - **売上・在庫**: 指標3つ(直近4週の販売数と増減%、在庫が何週分か、12週の売上)、**週ごとの販売数の棒グラフ**、**在庫の推移の折れ線グラフ**(在庫が少ないラインつき)。グラフは12週分。マウスを乗せると、その週の値が出る。
  - **販売方針・販促**: MD の販売方針、販促の期間、販促計画(週ごとの予定)。位置づけ(主力 / 定番 / 在庫調整 など)がバッジで出る。
  - **基本情報**: 価格、在庫、売上トレンド、評価、季節、天候適性、説明。
- 選定や並べ替えなどの**操作は、ここでは行わない**(中ペインだけ)。

### 5.10 テンプレートの管理(ヘッダーの「テンプレート」ボタン)
- 左に一覧(「作成したテンプレート」と「標準」)、右に詳細・編集、構成の見取り図(プレビュー)。
- **標準のテンプレートは、編集・削除できない**。「**複製して編集**」で、自分用に作り変える。
- 作成・編集できる内容: **テンプレート名、説明、ヒーローの種類(標準 / コラボ / 期間限定)、セクション**。セクションは、追加・削除・並べ替えができ、各セクションで、**種類(グリッド(2列)/ グリッド(3列)/ 特集)**、**商品の枠の数(1〜8点)**、**カテゴリ見出しの有無**を決める。セクションは最大6つ。
- 作ったテンプレートは、**組織の全員が選べる**(Dataverse に保存)。他の人が作ったものも編集できる。
- 削除すると、そのテンプレートを使っていたカードは、Standard4 として扱われる。

### 5.11 日本語 / English
- ヘッダーの切り替えで、**画面全体**が、日本語・English になる(初期値は、ブラウザの言語)。
- **AI の出力**も、画面の言語に合わせる(理由・切り口・制作指示など)。コピー・ヘッドラインの言語は、別に選べる(国に合わせる / 日本語 / English)。
- 日付・価格の表記も、言語に合わせる。

### 5.12 外部ユーザー(ゲスト)への共有
- 外部のユーザーも、Copilot Studio の接続を作らずに、AI の機能を使える(AI の呼び出しは、サーバー側のフローが代行する)。
- 利用には、環境側の設定(ゲストのアクセスを許可)と、アプリの共有、権限の付与が必要。

## 6. AI の仕組み(概要)

- AI は、**Copilot Studio のエージェント**。アプリが、必要な情報(配信の国・日時・テーマ、候補の商品・画像など)を渡し、エージェントが**候補の中から選ぶ**。商品・画像を作り出すことはない。
- 呼び出しは、データベース(Dataverse)の「AI要求」テーブルと、**Power Automate のフロー**を経由する(ゲストでも使えるようにするため)。待ち時間は、1回あたり**数秒〜十数秒**。
- 在庫・売上トレンド・評価・季節・天候・週次の実績・MD の方針は、**Dataverse のデータ**を元にする。

## 7. データ(デモ用のサンプル)

| データ | 内容 |
|---|---|
| 商品 | JP 30点(円)、US 30点(ドル)。カテゴリ: アウター / トップス / ボトムス / シューズ / 小物 / バッグ / ホーム |
| メイン画像 | JP 20点、US 20点(新作 / 特集 / セール / 会員 / イベント) |
| 配信カード | 合計 30件(US 向け 17件、JP 向け 13件。2026年10月の予定) |
| 週次実績 | 全60商品 × 12週(販売数、売上、在庫) |
| 販売方針 | 全60商品(MD の方針、販促計画、期間、位置づけ) |
| 画像 | デモ用のイラスト(実際の商品写真ではない) |

すべて**架空のデータ**。

## 8. 技術(概要。詳細は ARCHITECTURE.md / DATAVERSE.md)

- **Power Apps Code App**(React + TypeScript)。画面のデザインは **Fluent 2**(Microsoft の UI)。
- データは **Dataverse**。AI は **Copilot Studio + Power Automate**。
- 共同開発: GitHub。反映は `npm run deploy`(安全装置つき)。

## 9. 未実装・制限(**できると書かないこと**)

- **プッシュ通知のレイアウトのテンプレート**は作れない(テンプレートの管理は、メールのみ)。
- **AIチャットの会話の保存・再開**はできない(画面を閉じると消える)。**条件のピン留め**(以後のすべてのAI生成に効かせる)も、未実装。
- **メールの実配信**は、しない(このアプリは、配信内容の**企画**まで。配信システムとは連携していない)。
- 商品情報の売上・在庫は、**デモ用のダミーデータ**で、実際の基幹システムとは連携していない。
- 商品画像は、仮のイラスト。実画像の取り込みは、画像 URL を入れれば、できる仕組み。
- AI の案は、**採用するまで反映されず、保存もされない**(一部の選定は、反映して「元に戻す」)。
- 承認フロー(誰が承認したか、履歴)はない。ステータスは、手で変える。
- 商品が数千件以上の規模では、読み込み・検索・AI の候補の絞り込みの対策が、今後必要(デモ規模は問題ない)。
- AI の返答は、毎回同じとは限らず、まれに形式が崩れて、自動でやり直すことがある。
- AI の利用や、外部ユーザーの利用には、費用(従量課金)が発生する場合がある。

## 10. デモの流れの例(約5分)

1. **カレンダー**を見せる: 色分け、絞り込み(国 = US)、日英の切り替え。
2. 空の配信カードを開く → 「**すべてAIで下書き**」→ 進み具合 → 結果(テーマ、メイン画像、ヘッドライン・コピー、セクションの商品、制作指示)。
3. **プレビュー**: ヘッドラインの縮小、商品のドラッグ、プッシュへの切り替え。
4. **商品選定の理由**を見せる → **AIチャット**で「レインブーツを必ず入れて」→ 反映 →「どう思う?」→ 答えだけが返る。
5. **商品情報ペイン**を開く → 商品を押す → **売上・在庫のグラフ**、MD の方針。
6. **テンプレートの管理**: 標準を複製 → 3列グリッドのセクションを足す → 保存 → カードで選ぶ。
7. **English に切り替え**: 画面と AI の出力が英語になる。

## 11. 用語集

| 用語 | 意味 |
|---|---|
| 配信カード | 1回の配信の企画(1件のカレンダーの予定) |
| テーマ | 配信全体の前提。メールには出ない |
| ヘッドライン | メイン画像の上に載る大見出し |
| コピー | ヘッドラインの下の導入文 |
| メイン画像 / ヒーロー | メールの上部の大きな画像の枠 |
| セクション | メールの中の、商品を並べるまとまり(グリッド / 特集) |
| テンプレート | メールの構成の型(ヒーローの種類と、セクションの組み合わせ) |
| 制作指示 | 制作担当に渡す指示文 |
| 切り口 | AI の案の方針(「季節感」「商品の魅力」など) |
| 工程 | 企画の5つの段階(テーマ、テンプレート、ヒーロー、セクション、制作指示) |
| 市場 | 商品・画像の対象の国(JP / US) |

## 12. スクリーンショット(docs/screenshots/)

画面の画像は、**サンプルデータ(docs/*.csv)と模擬の AI の返答**で作ったものです(実データは写っていません。AI の文言は決まった例です)。
ファイル名は `ja-`(日本語の画面)/ `en-`(English の画面)+ 番号 + 内容。2 倍の解像度(PNG)です。

| 番号 | 内容 | 使いどころ |
|---|---|---|
| 01-calendar | 配信カレンダー(月表示・状態の色分け・フィルタ) | 画面の流れ、全体像 |
| 02-card-dialog | 配信カードの 4 ペイン(情報 / コンテンツ生成 + AIチャット / プレビュー / 商品情報) | 中心の画面 |
| 03-product-info | 右端の商品情報ペインを開いた状態 | 商品情報 |
| 04-theme 〜 07-sections | コンテンツ生成の各タブ(テーマ / テンプレート / ヒーロー / セクション) | 工程の説明 |
| 08-ai-theme-ideas | AI のテーマ案(理由つき・「採用」で反映) | AI 支援 |
| 09-ai-hero | AI のメイン画像の選定と候補 | AI 支援 |
| 10-ai-section | AI のセクション選定(見出し・コピー・商品) | AI 支援 |
| 11-ai-chat-update | AI チャットで指示 → 案を作り直し | AI チャット |
| 12-ai-chat-answer | AI チャットで質問 → 案は変えず回答 | AI チャット |
| 13-product-detail | 商品の詳細(売上・在庫のグラフ、販売方針、基本情報) | 商品情報 |
| 14-template-manager | テンプレート管理(標準 + 作成したもの) | テンプレート |
| 15-template-custom | 作成したテンプレート(特集 1 点 + 3 列グリッド) | テンプレート |
| 16-template-new | 「新規作成」の入力フォーム(名前・説明・ヒーローの種類・セクション) | テンプレートの作成 |
| 17-template-duplicate-edit | 標準を「複製して編集」した画面(名前が「…のコピー」になる) | テンプレートの作成 |
| 18-template-add-section | 「セクションを追加」で、2 つめのセクションを足した状態 | テンプレートの編集 |
| 19-template-3col | 2 つめを「グリッド(3列)・3点」にして名前を付けた状態(右の見取り図に反映) | テンプレートの編集 |

作り直すとき: `npm run screenshots`(Edge が必要。サーバーは自動で起動)。仕組みは `vite.mock.config.ts`(サービスを `src/mock` に差し替え)と `scripts/screenshots.mjs`。
